# Telegram через GREEN-API

Минимальный клиент для уже авторизованного Telegram-инстанса: подключение, создание личного чата по международному номеру, отправка текста и последовательный приём через HTTP API. Интерфейс адаптирован для desktop и телефона.

## Запуск

Проверенная среда: Node.js 22.20.0, pnpm 11.25.0. Требуется Node >=22.12. Версии пакетов зафиксированы в `pnpm-lock.yaml`.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Откройте http://127.0.0.1:5173. Введите API URL, idInstance и apiTokenInstance из кабинета GREEN-API. Начальный API URL: `https://4100.api.green-api.com`. Его можно изменить в форме или задать открытой переменной `VITE_GREEN_API_URL` (пример в `.env.example`). **Не создавайте переменные VITE_API_TOKEN / VITE_ID_INSTANCE для реквизитов.** Реальных токенов в проекте нет.

В кабинете заранее авторизуйте Telegram-инстанс и установите:

```json
{
  "webhookUrl": "",
  "incomingWebhook": "yes",
  "outgoingWebhook": "yes",
  "stateWebhook": "yes"
}
```

Приложение проверяет настройки, но не изменяет их. Для статусов delivered/read проверьте также настройки `outgoingMessageWebhook` и `outgoingAPIMessageWebhook` по документации провайдера. Эхо исходящих событий приложение игнорирует, чтобы не дублировать отправленные сообщения.

Используйте выделенный инстанс: другое приложение не должно читать его очередь. Web Locks ограничивает consumer между вкладками этого origin; без Web Locks используйте только одну рабочую вкладку. Для восстановления приёма после исправления доступа, настроек или конфликта вкладок выйдите и подключитесь снова.

## Поведение и ограничения

- Поиск номера выполняется только по submit. Номер должен начинаться с `+`. `exist:false` может означать скрытый настройками приватности номер.
- Ответ CheckAccount задаёт канонический chatId, используемый для отправки и входящих сообщений. Входящий личный текст автоматически создаёт чат.
- Один send на чат одновременно. Enter отправляет, Shift+Enter добавляет перенос; IME учитывается. При таймауте/обрыве статус «Результат неизвестен»: повтор может создать дубль, автоматических повторов нет.
- «Принято API» означает ответ с idMessage, а не доставку. Поддерживаются отдельные статусы delivered/read/failed/noAccount.
- Лимит 4096 консервативно проверяется в UTF-16 code units: длинная строка emoji может отклоняться раньше. Точная единица провайдера требует живой проверки.
- История и токен существуют только в оперативной памяти. Reload/выход удаляет историю; уже подтверждённые уведомления не восстанавливаются. Приложение подтверждает очередь после записи в память.
- Токен не передаётся в Redux, RTK Query arguments, persistence или собственные логи. В SPA токен виден браузеру и его сетевым инструментам, поскольку входит в URL API.
- Группы, медиа, постоянная история, синхронизация других Telegram-клиентов и авторизация QR/SMS не реализованы.

## Проверки

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e
```

E2E использует установленный Microsoft Edge и перехватывает сеть обезличенными fixtures, не отправляя сообщения реальным людям. Для CI установите Edge либо настройте Playwright на установленный Chromium. Unit/integration используют Vitest, Testing Library и MSW.

Живой сценарий с реальным Telegram-получателем не выполнен. Доступность всех методов из production origin и фактическая доставка остаются отдельной проверкой; см. `docs/api-contract.md`.

## Публикация

`pnpm build` создаёт `dist/` для статического HTTPS-хостинга. `pnpm preview` служит только для локальной проверки сборки. Настройте `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff` и CSP, например:

```text
default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self' https://4100.api.green-api.com; base-uri 'none'; object-src 'none'; frame-ancestors 'none'; form-action 'self'
```

При смене API URL измените connect-src. Не подключайте посторонние скрипты. Если CORS блокирует POST/DELETE, необходим ограниченный BFF по плану; сервер в эту сборку не включён.

## Структура

`app` — store и typed hooks; `entities` — модель истории и редьюсеры; `features` — подключение, поиск, отправка и receiver; `shared/api` — transport, схемы, RTK Query; `shared/session` — реквизиты и отмена; `pages` — композиция и лента. Селекторы/производные вычисления не создают вторую историю.
